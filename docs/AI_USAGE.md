## Cases where the assistant was wrong, and how it was caught
1. **RLS that failed open (earlier AI scaffold).** The previous scaffold's policy was
   `tenant_id = … OR current_setting('app.tenant_id', true) IS NULL OR … = ''`, so a
   missing tenant context returned every tenant's rows. Caught by reading the
   migration before building on it; replaced with a policy that matches nothing when
   unset, and `test_missing_tenant_context_returns_zero_rows` proves it.
2. **The checker approved invented facts.** First real drafts said "around 3 days",
   included a made-up email address, and recommended a non-existent "sales team", and
   all passed the original rules. Caught by reading persisted drafts from a real run;
   added `NUMBERS_GROUNDED`, `NO_UNGROUNDED_CONTACTS` and `CONTENT_SUPPORTED`.
3. **"Courtesy" replies leaked uncited claims.** The 1.5B model marked real requests as
   "asks for nothing", which sent them to an uncited acknowledgement path, producing
   "we don't handle returns for this product". Caught in the same draft review; the
   courtesy path now also requires category `other`.
4. **The test fake parsed the wrong message**, making a correct graph look broken.
   Caught by a failing test plus the persisted event trail.
5. **Tests overwrote the committed `out/` files** through the API's export call.
   Caught by comparing `out/decisions.jsonl` before and after `make test`; output dirs
   are now configurable and the suite writes to a temp dir.
6. **Re-running after a killed run would not finish the orphaned jobs** (they kept the
   old run id). Caught while designing the real kill test; re-runs now adopt them, and
   a test plus a real `kill -9` run confirm no duplicates.
7. **SSE pagination could skip events** across tenants when one tenant's page filled
   up. Caught in review; the merge now stops at the earliest full page.
8. **LangGraph checkpoints were outside RLS.** The first build documented this as a
   known limitation instead of fixing it. A follow-up audit proved the risk (a
   Harbor-bound database session could read Northwind ticket text from
   `checkpoint_blobs`, and the orchestrator accepted any thread id without a tenant).
   Fixed with migration 0002 and a tenant-bound checkpointer; the new tests were
   checked by disabling the fix and confirming 9 of 14 fail.
9. **The assistant approved drafts it had not read, under the candidate's name.**
   Earlier runs approved drafts with `--by drishti`, and a verification script
   approved a draft that inverted the cancellation policy. Both happened only in
   local or scratch databases. The committed `out/outbox.jsonl` comes from a fresh
   run in which every draft was read against the KB before approval, and the approver
   is recorded truthfully as `claude-code-session`, not as the candidate.
